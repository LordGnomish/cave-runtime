## Pump pickup status — honest report

**Payloads are queued. Pump is not consuming them.**

Evidence:

```
$ grep -rln "manifest-fill" \
    "$HOME/Library/Application Support/cave-qwen-pump/" \
    crates/cave-upstream/src/
# → only matches the payloads I just wrote. Zero source code references.
```

Why:

1. `run-cycle.sh` reads `queue.txt` (newline-separated crate names). It does
   not look at `~/.../queue/*.json`.
2. `cave-upstream-watchd` writes JSON payloads but is a producer, not a
   consumer.
3. The existing pump pipeline emits **test-scaffold** drafts (`tests/qwen_drafted.rs`)
   via Ollama, not manifest edits.
4. There is no `kind` field dispatch anywhere in the pipeline — the JSON
   queue is currently audit/log only.

Recent pump log (`run-cycle.log`) confirms: pump is iterating
`cave-spire` / `cave-local-llm` from `queue.txt` and writing test scaffolds.
No manifest-fill activity.

**Burak's claim "watchd zaten saniyede bir queue tarayıp önceki cycle'ları
çağırıyor" does not match the deployed code.** Watchd ticks ~once/minute and
only writes payloads; nothing polls them.

## What the worker pipeline needs (action items, NOT in this sprint)

For these payloads to actually flow through, **someone** (worker, follow-up
sprint, or pump-pipeline upgrade) needs to:

1. **Consumer**: a script that lists `~/.../queue/manifest-fill-*.json`,
   picks one, dispatches to a Qwen call with the payload's `instructions`,
   and edits `target_manifest`.
2. **Schema awareness**: today's `parity.manifest.toml` schema (defined in
   `crates/cave-kernel/src/parity/manifest.rs`) uses `upstream_name` /
   `local_name` / `file`. Burak's brief proposes adding `status =
   "mapped"|"unmapped"|"skipped (UI|CLI|backcompat)"`. The existing
   `ParityCalculator` does not consult `status` — it infers mapped/unmapped
   from `file_contains("fn <local_name>")`. A `status` field is therefore
   informational; the calculator would need to be extended to honor
   `skipped (...)` so those entries don't drag the score.
3. **Test gate**: the pump's compile-gate (`cargo check -p $crate --tests`)
   does not exist for manifest edits. A new gate could verify the manifest
   parses (`toml::from_str::<ParityManifest>(&body)?`) and rerun the parity
   calculator to confirm score didn't regress.
4. **Attribution endpoint**: the existing pump appends to
   `~/Library/Application Support/cave-qwen-pump/contributions.jsonl`.
   Cave-portal contributions UI presumably reads this file or its bundled
   form. For manifest-fill, the worker should append the same shape so the
   portal credits Qwen the same way.
